# 7天产品化上线计划

> 目标：把 `API Test Agent Pro` 从「个人可用 Demo」推进到「可以对真实用户开放首发版」。
> 范围：只做 P0 三件套，即 **沙箱、用户隔离、并发控制**，确保首发版安全、稳定、不翻车。

---

## 总目标

7 天后达到以下状态：

1. 用户可以通过网站上传 OpenAPI 文档并触发 `generate / heal / report`。
2. 每个用户任务都有独立 `task_id`，所有输出写入 `output/<task_id>/...`，互不覆盖。
3. pytest 子进程在沙箱下执行，至少具备：
   - 写路径白名单
   - 超时控制
   - 环境变量隔离
4. Web 入口有并发上限和排队逻辑，不会因为多人同时点击而把服务打挂。
5. 首发版保留 `host` 软沙箱，预留 `docker` 沙箱接口，后续平滑升级。

---

## 设计原则

### 1. 沙箱先软后硬

- 第 1 周先落地 `HostSandbox`，确保在不依赖 Docker 的情况下也能上线。
- 同时预留 `DockerSandbox` 接口，后续用户量上来后再切容器级隔离。

### 2. 所有任务强制隔离

- 任何生成结果、报告、diff 都必须写入 `output/<task_id>/...`。
- 不允许多个用户共享同一个 `generated_tests/` 或 `.cache/`。

### 3. 并发控制放在入口层

- Web 层负责限流、排队、rate limit。
- 执行层只负责单任务安全运行，不负责抢占式调度。
